# minicpm-o-uya

`minicpm-o-uya` is a pure Uya, Linux x86_64 CPU-first MiniCPM-o runtime bring-up. It is designed for auditable, tiny-fixture-first development: inspect GGUF files, audit MiniCPM-o/Qwen3 layouts, run deterministic text/vision/audio/speech/omni smoke paths, and keep every unsupported production feature explicit.

This repository does **not** wrap Python, PyTorch, llama.cpp, or the official MiniCPM-o runtime as runtime dependencies. Large model weights and media assets stay outside the repository.

## Status

Phase 20 documentation is current for the implementation through Phase 19:

- GGUF `inspect`/`audit`, tokenizer commands, tensor table/mmap inspection, scalar kernels, and selected quant kernels are implemented.
- Tiny Qwen3-like text binding, text generation, sampler controls, text `chat`, blocking `omni-chat`, `stream-chat` prototype, and `bench` smoke are implemented.
- Vision/audio/speech/omni paths are deterministic smoke/reference paths over tiny fixtures, raw inputs, and manifests.
- Full production MiniCPM-o omni inference is **not** claimed; unsupported model layouts, media codecs, and modality gaps should fail with diagnostics.

## Quick Start

```sh
make build
make fixtures
make test
build/minicpm-o-uya --help
```

Expected default validation uses only synthetic fixtures generated by `tests/make_tiny_gguf.py`:

```sh
build/minicpm-o-uya inspect tests/fixtures/tiny.gguf
build/minicpm-o-uya audit tests/fixtures/tiny.gguf
build/minicpm-o-uya bench tests/fixtures/tiny.gguf tests/fixtures/tiny_omni.json
```

## Usage

| Command | Purpose | Current scope |
| --- | --- | --- |
| `inspect <model.gguf>` | Print GGUF header, metadata, tensor table | Metadata/tensor directory only; does not read large tensor payloads |
| `audit <model.gguf>` | Diagnose MiniCPM-o/Qwen3 schema, branches, dtypes | Inspection/audit; does not imply generation support |
| `piece <model.gguf> <token-id>` | Print token piece | GGUF tokenizer metadata |
| `encode <model.gguf> <text>` | Encode text to token ids | Tiny BPE/special-token coverage |
| `decode <model.gguf> <token-id>...` | Decode token ids to text | Tiny tokenizer coverage |
| `format-chat <model.gguf> <user-text>` | Apply ChatML-like template | Qwen/MiniCPM-o style templates only |
| `tensors <model.gguf> [--mmap]` | Build tensor view table and cache skeleton | Bounds, dtype, mmap diagnostics |
| `qwen3-bind <model.gguf>` | Bind Qwen3 text config and weights | Tiny Qwen3-like fixture; real layouts may report missing tensors |
| `generate <model.gguf> <prompt> [sampler args...]` | Tiny text generation smoke | Deterministic reference path, not production generation |
| `chat <model.gguf>` | Minimal text REPL | Preserves context until tiny fixture context overflow |
| `vision-smoke <model.gguf> <image.raw>` | Vision tensor encoder smoke | `UYAI` raw F32 tensor input |
| `vision-preprocess-smoke <model.gguf> <image.rgb\|manifest>` | RGB/manifest preprocessing smoke | `UYRG`, `UYIM`, `UYVM`; no PNG/JPEG/MP4 decoding |
| `audio-smoke <model.gguf> <audio.raw>` | Audio encoder smoke | `UYAM` log-mel F32 input |
| `audio-preprocess-smoke <audio.pcm>` | PCM to tiny log-mel preprocessing smoke | `UYAP` PCM fixture input |
| `audio2audio-smoke <model.gguf> <audio.pcm\|audio.raw> [out.wav]` | Audio input to WAV smoke | PCM/mel -> audio encoder -> speech/vocoder WAV |
| `speech-smoke <model.gguf> <prompt> [out.wav]` | Speech/vocoder smoke | Deterministic tiny WAV output only |
| `omni-smoke <model.gguf> <manifest.json>` | Compile mixed text/image/audio/speech manifest | Fixed test JSON schema |
| `omni-chat <model.gguf>` | Blocking omni REPL | Text and manifest turns; speech output is queued/diagnosed, not full duplex |
| `stream-chat <model.gguf> <manifest.json>` | Streaming event prototype | Queue/ring/interrupt smoke over fixture events |
| `bench <model.gguf> <manifest.json>` | Tiny benchmark smoke | Deterministic reference timings and memory estimates |
| `bench <model.gguf> [--prompt TEXT] [--n-prompt N] [--n-gen N] [--repetitions N] [--threads N] [--no-warmup]` | Real text benchmark | Measures load/prefill/decode for Qwen3 path with live timings |
| `kernels-smoke` | Scalar kernel golden smoke | F32/F16/BF16/reference ops |
| `quant-smoke` | Quant kernel golden smoke | Selected GGML quant types |

Sampler arguments accepted by `generate` are validated by the tiny sampler path; unsupported or malformed values fail early instead of silently changing behavior.

`bench` now has two modes: the original `<model.gguf> <manifest.json>` smoke path stays deterministic for regression tests, while `bench <model.gguf> [bench args...]` runs a real text benchmark intended for apples-to-apples comparison with `llama-bench`.

## Supported Models And Formats

### Model/Layout Scope

- GGUF v2/v3 metadata and tensor directory inspection are supported for external files.
- The tiny Qwen3-like fixture is the only fully validated text generation layout in this repository.
- MiniCPM-o GGUF files can be inspected and audited for branch counts, metadata, tensor names, dtypes, and obvious missing pieces.
- Real MiniCPM-o/Qwen3 community GGUF files may require additional tensor-name, config, dtype, or modality binding work before generation.
- If a real model fails, run `audit` first and treat the diagnostic as the compatibility boundary.

### Input Fixtures

| Format | Magic | Used by | Notes |
| --- | --- | --- | --- |
| GGUF | `GGUF` | model commands | v2/v3 metadata/tensor directory; tensor payload used only by runtime smoke paths |
| Raw image tensor | `UYAI` | `vision-smoke` | NCHW little-endian F32 tensor |
| Raw RGB image | `UYRG` | `vision-preprocess-smoke` | Row-major uint8 RGB |
| Image manifest | `UYIM` | `vision-preprocess-smoke` | Embedded `UYRG` images, tile metadata |
| Video manifest | `UYVM` | `vision-preprocess-smoke` | Embedded `UYRG` frames; no video codec decoding |
| Log-mel audio | `UYAM` | `audio-smoke` | Little-endian F32 mel bins |
| PCM audio | `UYAP` | `audio-preprocess-smoke`, `audio2audio-smoke` | Tiny PCM fixture for preprocessing smoke |
| Omni JSON | JSON | `omni-smoke`, `stream-chat`, `bench` | Fixed tiny schema generated in `tests/fixtures` |
| WAV | RIFF/WAVE | `speech-smoke` output | Deterministic tiny vocoder smoke output |

## DType Support

| Area | DTypes | Status |
| --- | --- | --- |
| Tensor parser | `F32`, `F16`, `BF16`, `Q4_0`, `Q4_1`, `Q5_0`, `Q5_1`, `Q8_0`, `Q8_1`, `Q2_K`, `Q3_K`, `Q4_K`, `Q5_K`, `Q6_K`, `Q8_K`, `IQ4_NL`, `I8`, `I16`, `I32`, `I64`, `F64` | Recognized in tensor metadata/table |
| Reference kernels | `F32`, `F16`, `BF16` | Loaded/dequantized to scalar F32 reference math |
| Quant dot smoke | `Q8_0`, `Q4_K`, `Q5_K`, `Q6_K`, `IQ4_NL` | Covered by deterministic fused dequant+dot tests |
| Other parsed dtypes | Listed parser dtypes not in kernel smoke | May inspect successfully but fail at runtime with tensor name and dtype |

## Unsupported Or Prototype Features

- No built-in PNG, JPEG, WebP, MP4, AAC, Opus, or microphone/camera capture; convert inputs externally to documented raw fixture formats.
- No GPU backend, WebRTC transport, server mode, or native real-time media IO.
- No guarantee of full MiniCPM-o production generation for arbitrary real GGUF layouts.
- `omni-chat` is blocking and preserves text output; speech output is reported as unsupported/queued there.
- `stream-chat` is a deterministic queue/ring/interruption prototype, not a production full-duplex assistant.
- `speech-smoke` and `audio2audio-smoke` write tiny deterministic WAVs and do not claim natural vocoder quality.
- Unknown tensor names, missing branches, unknown dtypes, or unsupported chat templates are compatibility work items, not silent fallbacks.

## External Model Smoke

Keep external files outside the repo:

```sh
export MINICPM_O_GGUF=/path/to/minicpm-o.gguf
export MINICPM_O_TEXT_GGUF=/path/to/qwen3-text.gguf
export MINICPM_O_IMAGE_RAW=/path/to/image.raw
export MINICPM_O_AUDIO_RAW=/path/to/audio.raw
export MINICPM_O_MANIFEST=/path/to/omni-manifest.json
```

Recommended order:

```sh
MINICPM_O_GGUF=/path/to/model.gguf make minicpmo-audit
build/minicpm-o-uya inspect "$MINICPM_O_GGUF"
build/minicpm-o-uya audit "$MINICPM_O_GGUF"
build/minicpm-o-uya tensors "$MINICPM_O_GGUF" --mmap
build/minicpm-o-uya qwen3-bind "$MINICPM_O_TEXT_GGUF"
build/minicpm-o-uya vision-smoke "$MINICPM_O_GGUF" "$MINICPM_O_IMAGE_RAW"
build/minicpm-o-uya audio-smoke "$MINICPM_O_GGUF" "$MINICPM_O_AUDIO_RAW"
build/minicpm-o-uya audio2audio-smoke "$MINICPM_O_GGUF" "$MINICPM_O_AUDIO_RAW" /tmp/minicpm-o-uya-audio2audio.wav
build/minicpm-o-uya omni-smoke "$MINICPM_O_GGUF" "$MINICPM_O_MANIFEST"
build/minicpm-o-uya bench "$MINICPM_O_GGUF" "$MINICPM_O_MANIFEST"
build/minicpm-o-uya bench "$MINICPM_O_TEXT_GGUF" --n-prompt 512 --n-gen 128 --repetitions 5 --threads 28
```

If any step reports unsupported layout or missing tensors, keep the failing command output and extend the corresponding binding path before attempting generation.

## Golden Sources And Thresholds

Golden checks come from deterministic tiny fixtures generated by `tests/make_tiny_gguf.py`, not from bundled production weights:

- Tokenizer goldens cover English, Chinese punctuation, newlines, and `<image>`/`<audio>` placeholders as whole tokens.
- Kernel goldens compare scalar reference outputs for F32/F16/BF16 ops, normalization, RoPE, softmax, dense matvec, activations, Conv1D, and Conv2D.
- Quant goldens compare fused dequant+dot against scalar dequant references for `Q8_0`, `Q4_K`, `Q5_K`, `Q6_K`, and `IQ4_NL` within fixture thresholds.
- Vision/audio/speech/omni goldens use stable checksums, shape/span counts, and expected diagnostics instead of visual/audio quality claims.
- Benchmark reference error is expected to print `text=0.000000 vision=0.000000 audio=0.000000 vocoder=0.000000` on the tiny fixture.

## Troubleshooting

| Symptom | Likely cause | Next step |
| --- | --- | --- |
| `cannot open file` | Wrong path or unset environment variable | Check `pwd`, `ls`, and the `MINICPM_O_*` variable values |
| `bad magic` | Command received the wrong file format | Use GGUF for model commands and `UYAI`/`UYRG`/`UYAM`/`UYAP` for raw smoke commands |
| `short file` | Truncated model or fixture | Regenerate fixtures with `make fixtures` or re-download the external file |
| `data extends past file end` | Tensor directory points beyond file size | Recreate the GGUF and run `inspect`/`audit` before runtime commands |
| `unknown ggml_type` | DType is not in the current parser/runtime table | Record tensor name/dtype and add parser/kernel support |
| `missing tensor ...` | Model layout or tensor naming is unsupported | Run `audit`, compare expected names, and add a binding alias or layout path |
| `unsupported chat template` | Template is not ChatML-like or currently recognized | Inspect tokenizer metadata and add a template adapter |
| `context overflow` | Prompt/history exceeds tiny context | Shorten input or restart the REPL/session |
| Missing `audio`, `vision`, or `speech` branch | Command requires modality weights absent from GGUF | Use a model with that branch or run a text-only command |
| PNG/JPEG/MP4 input fails | Native codecs are intentionally not implemented | Convert externally to `UYRG`, `UYAI`, `UYIM`, or `UYVM` fixtures |
| Speech missing in `omni-chat` | Blocking omni chat does not synthesize speech | Use `speech-smoke` for tiny WAV smoke and treat full speech chat as future work |

## Architecture

```text
GGUF file ──► binary reader ──► inspect/audit ──► tensor table/mmap
                                  │                 │
                                  │                 ├─► tokenizer/chat template
                                  │                 ├─► Qwen3 text binding ─► generate/chat
                                  │                 ├─► vision binding + UYAI/UYRG/UYIM/UYVM preprocess
                                  │                 ├─► audio binding + UYAM/UYAP preprocess
                                  │                 └─► speech/vocoder smoke ─► tiny WAV
                                  │
Omni JSON/stream events ──────────┴─► prompt compiler ─► omni-smoke/omni-chat/stream-chat/bench
```

Data is kept CPU-first and small-fixture-first: parsers establish safe views, binders validate tensor names/shapes/dtypes, smoke commands exercise deterministic reference paths, and unsupported production gaps return explicit diagnostics.
